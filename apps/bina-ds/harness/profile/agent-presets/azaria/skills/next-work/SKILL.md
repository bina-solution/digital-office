# /next — כל העבודה הפתוחה, והצעה לסבב הזה

הפקודה `/next` (תוסף `@bina/dsh-command-next`) מתחילה תור עם הבריף הזה. גם בלי הפקודה — זו המיומנות
שמפעילים כשאומרים "מה עכשיו".

**העיקרון:** העבודה הפתוחה מוצהרת בקבצים, לא נשמרת בזיכרון של סשן. ה-Plane הוא ה*תצוגה* של ההצהרה
(`plans/*.yaml`), ומצב הביצוע שלו נשמר ב-Plane עצמו. לכן סורקים את המקורות לפי הסדר, אומרים מה לא
נסרק באמת, ורק אז מציעים.

## 1. סריקה — המקורות, בסדר הזה

```bash
# (א) ההצהרה: כל פריט בכל מודול, לפי עדיפות — עובד גם כש-Plane למטה
python3 <skills>/next-work/overview.py            # ברירת מחדל: השורש הוא ספריית העבודה
python3 <skills>/next-work/overview.py --json     # לאיסוף מדויק

# (ב) מצב הביצוע ב-Plane (רק כשהוא נגיש — הוא רץ בלשכת HP)
./bbox project-pln tasks list --as azaria                 # שלי
./bbox project-pln tasks list --as azaria --state started  # מה כבר בתהליך
./bbox project-pln tasks show DGO-<n>                      # הסעיף "קבלה" = ההגדרה של בוצע

# (ג) מה שהבעלים דיווח לאחרונה (הצילום/ההודעה שפתחה את הסבב) — ומה שכבר נפתח ממנו כפריט

# (ד) מצב הלשכה והקישורים — הרבה "תקלות" הן בעצם לשכה מקושרת למטה
./bbox dgo                      # הלשכות המוצהרות ומצב הריצה שלהן
curl -s http://dgo-extend:8983/api/link | python3 -m json.tool | head -40
./scripts/dc ps                 # מי לא healthy

# (ה) באגים פתוחים עם מדידות (כל אחד מהם הוא פריט או מועמד לפריט)
ls issues/*.yaml                # status: open / in-progress / blocked
```

## 2. סינון ודירוג — איך בוחרים "הבא"

מדרגים לפי הסדר הזה, ובכל דירוג מעדיפים את מה שאפשר **לסיים ולהוכיח** בסבב אחד:

1. **הלשכה עצמה שבורה** (הקישור, הקונסול, ה-SSO, ה-drive, מנוע/דיסק) — הכל תלוי בזה, וזה מה שהבעלים
   מרגיש מיד. פריטים ב-`o-link`, `o-eng`, ואירועים ב-`issues/` עם `severity: high` ו-`status: open`.
2. **מה שהבעלים ביקש בסבב האחרון** — בקשה טרייה שלא נפתחה כפריט היא הפרה של המיומנות `plane-tasks`:
   פותחים אותה קודם, ואז מבצעים.
3. **מה שחוסם אחרים** (פריט שמסומן כחסימה לפריטים נוספים, או שמשחרר לשכה שלמה).
4. **עדיפות גבוהה עם הקבלה מוכחת** — `priority: high`/`urgent` שה"מה נדרש" שלו נגמר בבדיקה שאפשר להריץ.
5. **זול ומשפר אמון** (שער אדום אחד, מסמך שמתקן סתירה, באג עם root cause ידוע).

**מה לא להציע:** פריט שתלוי רק בהחלטת בעלים (אלא אם מציעים את ההחלטה עצמה), פריט שממתין למכונה שאינה
ברשת, וכל דבר שמבטיח "אני אבדוק" בלי קבלה.

## 3. הפלט לבעלים — קצר, מדורג, בעברית

- **מה דחוף** (1–3 שורות, כל אחת עם הפריט: `DGO-<n>` או מפתח התוכנית).
- **מה חסום ולמה** — ומי משחרר: אני, הבעלים, מכונה, או ספק.
- **מה מחכה לבעלים** — החלטה/סיסמה/מכונה, בלשון של פעולה אחת.
- **ההצעה שלי לסבב הזה**: 1–3 פעולות, ולכל אחת — למה עכשיו, ומה ההוכחה שתראה בסוף (פקודה, שער, צילום).
- **מה לא נסרק** (Plane למטה, קישור למטה) — במפורש, לא בהשמטה.

## 4. ואז?

ההצעה היא לא ביצוע אוטומטי: הבעלים בוחר. אחרי הבחירה — הפריט עובר ל-`start` (`plane-tasks`), העבודה
נעשית לפי `office-operations`/`office-app-builder`, ובסוף `done` עם הוכחה. בקשה חדשה של הבעלים בדרך
נפתחת כפריט **לפני** שהיא נעשית.
