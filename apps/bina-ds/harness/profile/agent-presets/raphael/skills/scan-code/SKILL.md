# סריקת קוד — רפאל

כל הפקודות רצות מתיקיית ה-checkout (ספריית העבודה שלך), בתוך הקונטיינר `bina-ds`. אתה **סורק ומציע**, לא מתקן: כל שינוי בקוד הוא של עזריה או של הבעלים. הפלט שלך הוא ממצא מבוסס + הצעת ריפוי (מה, היכן, מדוע, וההשפעה), ובמידת הצורך פריט ב-project-pln והודעה במרכז ההתראות (source `raphael`).

## השערים — מקור האמת לאיכות הקוד

| מה | פקודה |
|---|---|
| חבילת השערים כפי ש-CI מריץ (strict) | `bash scripts/ci/gates.sh` |
| כל השערים, מפורט | `python3 scripts/refactor/run-gates.py --all` |
| שער בודד | `python3 scripts/refactor/run-gates.py <gate-name>` |
| הלֵיין החי (צריך לשכה רצה) | `python3 scripts/refactor/run-gates.py --live` |
| מה כל שער בודק | `scripts/refactor/GATES.md` (טבלה G0…; קרא לפני שאתה מציע תיקון) |

קרא את ה-tally: `PASS`/`FAIL` לכל שער. לכל `FAIL` — פתח את ה-GATES.md של אותו שער, בסס מה הוא מצא (הרץ אותו לבד עם הארגומנטים שלו), ונסח הצעה שמפנה לקובץ ולשורה ול-fix hint שהשער מדפיס.

## קריאה נכונה של אדום

- **אדומים שממתינים לבעלים** אינם „לתקן” — הם החלטה שלו, מתועדת ב-project-pln. נכון לכתיבת מיומנות זו: `gallery-default-lint` (DGO-408), ולעיתים `swallowed-subcall`/`n8n-loop-order`/`app-tag` כשאין לשכה עם INDOX. אל תציע „תיקון” להם; הצבע על פריט העבודה הקיים.
- **verdict אמיתי מול עץ עבודה מלוכלך**: אם ה-checkout מחזיק שינויים לא-מחויבים (למשל של סשן אחר), הרץ את השערים ב-worktree נקי של ה-commit — `git worktree add --detach <path> <commit>` (מ-Git Bash על Windows; WSL git לא עוקב אחרי ה-.git של worktree), ואז `scripts/ci/gates.sh` בתוכו. שערים שמסתמכים על `git ls-files` (G80 undefined-name, G77 screen-words) ידווחו „blind → FAIL” ב-worktree שבו ה-ls נכשל — זה ארטיפקט, לא אדום אמיתי.
- **אימות לפני „נקי”**: שער ירוק אמיתי רק כשהסריקה מצאה קבצים. „No module named pytest” / „no file found” = לא עבר, גם אם rc=0 בטעות.

## קומפוזיציה, צורה, פרט

מעבר לשערים: חפש כפילויות (אותה לוגיקה בכמה מקומות — נוגד את „declare, don't restate”), מימושים חלקיים, קוד מת, ומחרוזות גולמיות שאמורות לעבור דרך הבלוקים המשותפים (bina-said/bina-ask/theme-tokens — ראה G27). כל אלה הצעות, לא עריכות.

## מה לא לעשות

אל תריץ `docker compose` ישירות (G7). אל תערוך קוד כדי „להעביר” שער. אל תשנה בדיקה או תיעוד כדי שמשהו יעבור — אם בדיקה צריכה להשתנות, זה ממצא בפני עצמו, מדווח בנפרד.
