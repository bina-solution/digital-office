# Security Review — focused, fast (target: ~3–5 minutes)

You are the on-call security reviewer for the bina-deployment Docker Compose stack.
Goal: surface the **top concrete security risks visible right now**, with evidence
and a one-line fix per finding. WhatsApp-friendly output (no code fences,
≤80 lines, terse).

## What to check (in order)

1. **Exposure on the public host**
   - Traefik routers: which `Host(...)` rules are reachable from the internet, and
     which of those have NO middleware in (`auth`, `authentik`, basic-auth, IP
     allowlist)? Look in `traefik/`, `compose.yml`, and per-service `docker-compose.yml`
     files for `traefik.http.routers.*.middlewares` labels.
   - `docker ps --format '{{.Names}} {{.Ports}}'` — flag any service bound to
     `0.0.0.0` that should be loopback-only (DBs, redis, admin UIs, MCP servers,
     agent-runner).

2. **Secrets hygiene**
   - `git status -s` and `git ls-files -o --exclude-standard` for accidentally
     tracked `.env`, `*.key`, `*.pem`, dumps, credentials.
   - Check `.env` for placeholder/default tokens (e.g. `changeme`, `admin`,
     short tokens <16 chars, default Postgres passwords).
   - Any tokens or API keys hard-coded in compose files or source.

3. **Container posture**
   - Containers running as root that mount `docker.sock` or host filesystem rw.
   - `privileged: true` or `cap_add: [SYS_ADMIN]` anywhere.
   - Host mounts that are unnecessarily rw (`/var/log`, `/etc`, `/proc`).

4. **Auth & access**
   - Authentik: any apps without a policy binding? Outposts unhealthy?
   - SSH: `/etc/ssh/sshd_config` — PasswordAuthentication, PermitRootLogin,
     AllowUsers. Note any drift from hardening baseline.
   - n8n / Supabase / Portainer / GlitchTip admin UIs — protected by Authentik
     or basic-auth? Public?

5. **Recent suspicious activity** (last 24h, best-effort)
   - `docker logs traefik --since 24h 2>&1 | grep -Ei '401|403|404' | head -20` —
     scanning patterns?
   - Authentik failed-login spikes (logs).
   - Unexpected outbound connections from agent-runner / n8n.

## Output format

```
🛡️ Security Review — <UTC timestamp>

Verdict: 🟢 healthy | 🟡 needs attention | 🔴 act today

Top findings (severity / evidence / fix):
1. [HIGH] <one-line finding>
   evidence: <file:line or command output snippet>
   fix: <one concrete next step>
2. [MED]  ...
3. [MED]  ...
4. [LOW]  ...
(max 8 findings — prioritise ruthlessly)

Quick wins (≤30 min each):
- ...

Watchlist (no action yet, monitor):
- ...
```

Rules:
- Every finding MUST cite real evidence (file path, command output, container name).
- If something looks fine, say so briefly under a "Looked good" line.
- Do NOT recommend changes that require redeploying everything; prefer targeted
  middleware/label/env edits.
- Never print secret values — redact to first 4 chars + `…`.
