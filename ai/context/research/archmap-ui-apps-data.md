## 4 · The data layer

INDOX instances live only in `public.indox_instances`; the file block is a bootstrap seed (platform.state.yaml:109-120). ## 5 · Smells and risks (with evidence)

1. **Duplication is the architecture.** 35 palette copies, 24 `bina-ask`, 20 `bina-said`, 12 nav-js, 7 icon sets; the console's `app.js` alone carries 94 + 155 lines of stamped blocks. Only the lint keeps them identical; two carriers hold blocks inside JS template strings, where a backtick in a comment broke two servers for a day (G27 row). Every new shared behaviour = a new block + TARGETS list + `--fix` across the tree.
2. **The simulation is a second UI that drifts.** PORT-PLAN calls it "the specification" (:13-15), yet `build.mjs` retired the drive and mail forks because the **live** apps went further (:29-39); INDOX is still a fork; `sim/overlay/*.js` is a third place rules live; the 7.7 MB artifact is committed; after the refactor it could not be rebuilt at all (:19-25).
3. **A server per screen, each proxying.** 23 first-party servers for mostly static pages: Flask ×9, FastAPI ×11, aiohttp ×1, Node `http` ×2, Go ×1, plus four vendored stacks (Plane, n8n, OpenHands, the Harness). The console proxies everything, app-management shells to `reconcile.py` and compose, and each app re-implements the Sentry block and a request helper (why `bina-said` exists).
4. **Frame-of-frames.** Public site → sim (1440×900) → shell → `#frame` `/a/<alias>/` → app → inner viewer iframe (drive, mail, my-docs): five documents deep; desktop mode runs ≤ 40 iframes, 10 live; a remote tile is a proxy of a proxy (`/a/<alias>.<office>/` → dgo-extend → peer console → app). Every byte crosses one threaded Flask process — the 55 s SSE cap exists because it ran out of threads (app.py:860-868).
5. **RTL/Hebrew is per-screen craft, not a layer.** 17 screens declare `<html lang="he" dir="rtl">`, one bare `<html>`; the table reverses columns to fool an LTR engine; the harness gets RTL from a plugin matching hashed CSS-module suffixes (brand-bina client.js); Hebrew fell to a serif on Windows unseen for weeks (memory); G89 had to be written for "1 פריטים".
6. **Phone is viewport-decided, but four ways.** Shell `matchMedia 640`, nav by container width, apps at 820/1024, the vendored grid by `navigator.userAgent` (revo-grid.entry.js:1132–1133); a desktop window re-flows an app at a narrower viewport, so an app sees "phone" inside a desktop (desktop.js:294-296). Only the first-party code avoids UA sniffing.
7. **Data without a hook.** 37 of 44 manifests have no `hooks/backup`: SQLite (`notifications.db`, the harness's session store), the vault and `grants.jsonl` are tarred live (torn-snapshot risk); the WireGuard key is covered by nothing; indox keeps its working set in a bind it does not declare; bina-ds writes outside its declaration; `backup-coverage` was closed as "the headline count was the wrong question" (issues/…15-of-21…yaml) with the per-app table still owed.
8. **Trust boundaries bend for convenience.** The agent has root on the engine and rw on the shared checkout (three writers in one tree); a remote app on a `*.localhost` office runs in the console's origin by design (app.py:484-490); the identity header has 10 runtime consumers where the graph declares 3 (G83); `auth_exclude` is accepted by the schema and ignored by the emitter.
9. **Two branches, two agents.** The pulse/wake machinery lives on `hp-dgo` and was deleted on `vps1-dgo` by owner ruling; the harness is pinned at an alpha; a profile-in-volume mistake took every conversation down for 41 minutes.
10. **Stale owners' notes.** `platform.state.yaml:1` names the console as writer; BYFA says `on_uninstall: keep|purge` while the schema default is `prompt`; `issues/backup-coverage…` is closed while its resolution (per-app table + gate) is not in the tree.
