## למה

רוב מה שהלשכה יודעת לא נמצא בתיקייה שלה. מסדי הנתונים, האוטומציות, המסמכים, המשתמשים ומצב הסנכרון נמצאים בנפחים של Docker, מחוץ לתיקייה. `zip` של התיקייה יחזיר לשכה שעולה ולא יודעת כלום.

`bbox export` שומר את כל זה בארכיון אחד.

## לפני שמתחילים

- הלשכה רצה.
- יש מקום בדיסק בשביל הארכיון.

## השלבים

1. **גבו:**

   ```bash
   ./bbox export
   ```

   הארכיון נכתב ל-`exports/` בתוך התיקייה של הלשכה, בתיקייה עם שם הלשכה, סוג הגיבוי והזמן.

2. **בחרו כמה לשמור.** ברירת המחדל היא `full`: הכול, כולל היסטוריית ההרצות והמטמון של קריאת המסמכים. בלי אותם:

   ```bash
   ./bbox export --mode config
   ```

3. **שמרו את הארכיון במקום אחר.** הארכיון מחזיק גם את `.env` ואת המפתחות. שמרו אותו כמו שאתם שומרים סיסמה.

   `bbox export` מסרב לכתוב לתיקייה ש-`git` לא מתעלם ממנה, כדי שהסודות לא ייכנסו למאגר.

## אפליקציה אחת בלבד

```bash
./bbox export --app <app>
```

ארכיון רק של הנתונים של האפליקציה הזו.

## לפני מעבר למחשב אחר

```bash
./bbox export --quiesce
```

`--quiesce` עוצר את מי שכותב לנתונים בזמן הגיבוי, ומפעיל אותם שוב בסוף. כך כל מסדי הנתונים נשמרים מאותו רגע. זה נכון למעבר, ולא לגיבוי של לשכה שעובדים בה.

## אם הגיבוי נקטע

הריצו שוב את אותה פקודה. מה שכבר נשמר לא נכתב שוב.

## איך בודקים שזה עבד

בתיקייה של הארכיון יש קובץ `manifest.json`. הוא מונה כל קובץ שנשמר.

```bash
ls exports/
```

הבדיקה האמיתית של גיבוי היא שחזור. ראו [שחזור](/he/backup/restore).
