## מה היא

«אוטומציות» (`n8n`) היא מנוע התהליכים של הלשכה. כל התהליכים של כל האפליקציות רצים בה: למשל הסנכרון של [מסמכים](/he/apps/indox) והתמלול של [פגישות וידאו](/he/apps/meet). היא למנהלים בלבד, ונמצאת באריח «n8n» בקבוצה «תשתית».

**היא רצה גם כשהיא כבויה.** בקובץ ברירת המחדל היא כבויה, אבל «בינה», «מסמכים», «קבצים» ו«מייל», שדולקות בהתקנה חדשה, צריכות מנוע תהליכים, ולכן הלשכה מפעילה אותה בשבילן. גם «פגישות וידאו», «צ׳אט» ו«רפאל» צריכות אותה כשמדליקים אותן. כיבוי שלה לא עוצר אותה כל עוד אחת מהן דולקת.

## ממה היא בנויה

העורך וה-API, שירות שמקבל webhooks, שני עובדים, ובסיס נתונים משלה. העבודה עוברת בתור, והעובדים מושכים ממנו.

## התהליכים כתובים בקוד

כל אפליקציה מביאה את התהליכים שלה כקבצי `*.workflow.ts` בתיקייה שלה. **הקוד הוא המקור.** מה שרץ ב-n8n הוא עותק שנבנה ממנו.

| פקודה | מה היא עושה |
|---|---|
| `./bbox n8n status` | התהליכים, הפעילות והבריאות |
| `./bbox n8n pull <app> <wfId>` | מעתיקה תהליך אחד מ-n8n לקוד. עושים את זה ראשון |
| `./bbox n8n push <app> <wfId> --dry-run` | מה עדכון היה משנה |
| `./bbox n8n push <app> <wfId>` | מעדכנת את n8n מהקוד, מפעילה את התהליך מחדש וקוראת בחזרה. n8n עצמו לא מופעל מחדש |
| `./bbox n8n plan <app> <wfId>` | איך בודקים את התהליך |
| `./bbox n8n test <app> <wfId>` | מריצה את התהליך באמת, עם כל ההשפעות שלו |
| `./bbox n8n exec list` | ההרצות, לאבחון |

## איך מעדכנים תהליך בבטחה

1. מושכים בדיוק את התהליך שעורכים: `pull <app> <wfId>`.
2. עורכים את הקוד.
3. `push … --dry-run`, ואז `push` של אותו תהליך בלבד.

**`pull <app>` בלי מזהה** כותב מחדש מ-n8n כל קובץ של האפליקציה שאין בו עריכה שעוד לא עלתה, מוחק מהם את ההערות, ומוחק קובץ של תהליך חדש שעוד לא עלה. לא עושים את זה.

**התנגשות בעדכון** אומרת שמישהו שינה את התהליך ישירות ב-n8n. קודם בודקים מה השתנה. `--force` דורס את השינוי הזה.

**`test` מריץ באמת.** מריצים קודם `plan`.

## מה פתוח לעולם

העורך עומד מאחורי הכניסה של הלשכה, ומאחורי החשבון של n8n עצמו. רק שלושה נתיבים פתוחים לכל העולם, בלי כניסה: `/webhook/`, `/webhook-waiting/` ו-`/form/`. מי שקורא להם הוא מכונה אחרת, בלי כניסה, ולכן כל תהליך שמקבל webhook צריך לבדוק בעצמו מי פונה אליו.

## מה רק הבעלים עושה

- `push all` ו-`pull all`: הם פועלים על כל התהליכים, ו-`push all` גם מפעיל מחדש את n8n ואת העובדים.
- `./bbox n8n <app> unpush`, שמוחק את כל התהליכים של האפליקציה בלי לשאול, ומפעיל מחדש את n8n.
- כל פעולה שמוחקת או מאפסת את בסיס הנתונים של n8n.

## מה עוד לא עובד היום

- **n8n המקומי עולה תמיד.** אפשר להריץ את התהליכים של אפליקציה ב-n8n של לשכה אחרת בעדר. אבל גם כשהתוכנית של העדר (`herd.yaml`) מציבה את n8n בלשכה אחרת, הלשכה הזו בוחרת רק ממה שיש לה ומפעילה את n8n שלה. גם כיבוי מפורש לא עוצר את זה.
- **בשרת בלי node, תהליך חדש שאמור להיות פעיל נוצר כבוי.** העדכון בודק אם להפעיל תהליך חדש בעזרת `node` של השרת עצמו. בלי `node` התשובה היא «לא».
- **תהליך חדש עם תזמון** מתחיל לרוץ לפי התזמון רק אחרי הפעלה מחדש של n8n.
