## מה היא

«ניהול פרויקטים» (`project-pln`) היא Plane Community Edition שרצה בשרת של הלשכה: מקום עבודה מחזיק פרויקטים, ופרויקט מחזיק **פריטי עבודה**, לפי מצבים, תוויות ומודולים. היא בעברית ומימין לשמאל. היא כבויה בהתקנה חדשה, ונמצאת באריח «ניהול פרויקטים» בקבוצה «עסק».

מדליקים אותה במסך האפליקציות, שעושה את כל הדרך, או בשורת הפקודה. שם `apps enable` רק כותב את ההחלטה, ו-`./bbox run` מעלה את האפליקציה:

```bash
./bbox apps enable project-pln
./bbox run
```

## בלי אשף הקמה

Plane רגילה לא מכניסה אף אחד עד שמישהו ממלא מסך הקמה ביד. כאן ההקמה מוצהרת: ההרצה של `./bbox run` מקימה את מקום העבודה, הפרויקט, המצבים והתוויות, ויוצרת את חשבון הבעלים.

- **הכניסה של הבעלים** היא `PLANE_OWNER_EMAIL` ו-`PLANE_OWNER_PASSWORD` מ-`.env`. היא נשמרת בכספת, ואפשר לקרוא אותה ב[חיבורים ומפתחות](/he/apps/connections), בכרטיס של Plane. הכתובת חייבת להיות אמיתית: עם כתובת לדוגמה (כמו `@example.com` או `@local.dev`), ההקמה מדלגת על Plane ואומרת למה.
- **אין הרשמה עצמית.** טופס הרשמה פתוח הוא מכונה שמייצרת חשבונות.
- **כניסה דרך הלשכה, למי שנקרא בשם.** מי שהשם שלו כתוב ב-`sso.users` של `apps/project-pln/bootstrap.yaml` נכנס ל-Plane בלי טופס נוסף. בברירת המחדל כתוב שם רק `akadmin`. כל אחד אחר מקבל את טופס הכניסה של Plane. לשכה מקושרת נכנסת דרך הקישור, בחתימה של הקישור, לפי אותה רשימה.
- **בלי דיווח החוצה.** הדיווח של Plane ליצרן כבוי בקוד, לא רק בהגדרה.

## משורת הפקודה

| פקודה | מה היא עושה |
|---|---|
| `./bbox project-pln verify` | בודקת שאפשר באמת להשתמש בה: ה-API עונה, ההקמה במקום, והבעלים יכול להיכנס |
| `./bbox project-pln tasks show <REF>` | פריט עבודה אחד |
| `./bbox project-pln tasks start <REF>` | מעבירה פריט לעבודה. גם `done`, `take` ו-`comment` |
| `./bbox project-pln tasks attach <REF> <file>` | מצרפת קבצים לפריט |
| `./bbox project-pln plan <name> --dry-run` | מה תוכנית מוצהרת הייתה משנה: פרויקט, מצבים, תוויות, מודולים ופריטים. בלי `--dry-run` היא מחילה. היא מעדכנת ומוסיפה, ולא מוחקת כלום |
| `./bbox project-pln import-cloud` | מייבאת מקום עבודה מ-Plane Cloud, בשני שלבים. השלב הראשון יוצר את הפרויקטים החסרים, ריקים, וכותב תוכנית לבדיקה. `--apply` מעביר את הפריטים. צריך שני אסימונים: `PLANE_CLOUD_API_TOKEN` ו-`PLANE_LOCAL_API_TOKEN`. דפים וקבצים מצורפים לא עוברים |

## מה עוד לא עובד היום

- **פרויקט שהתוכנית יוצרת** מקבל רק את הבעלים כחבר, ולא את הסוכן של הלשכה. הסוכן לא רואה אותו עד שמוסיפים אותו.
- **בטלפון,** בעמוד של פריט, המצב, האחראים והעדיפות מופיעים מתחת לכל התיאור.
- **הבעלים מקבל טופס כניסה.** בלשכה חדשה הבעלים בוחר שם משתמש משלו בכניסה הראשונה, והשם הזה לא כתוב ב-`sso.users`. עד שמוסיפים אותו שם, Plane מבקשת ממנו להיכנס בטופס שלה.

## איך בודקים שהיא עובדת

מכולה ירוקה לא אומרת שההקמה הושלמה. `./bbox project-pln verify` אומרת: היא בודקת שהבעלים באמת יכול להיכנס.
