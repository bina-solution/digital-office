## מה היא

«ישויות» (`entities`) היא המקום היחיד שבו מגדירים את כל מי שהעסק עובד איתו. כל ישות היא **אדם** או **ארגון**,
ויש לה **תפקידים** — כמה בבת אחת. ארגון יכול להיות גם הלקוח שלנו וגם הספק שלנו.

העסק עצמו לא כאן: הוא מוגדר ב-[«זהות»](/he/apps/digital-assets/).

| תפקיד | למה | השדות שלו |
|---|---|---|
| חברה | הרשומה המשפטית שמסמך מדפיס | שם משפטי, ח״פ או מספר עוסק, סוג העוסק (רשימה סגורה), תיק מע״מ |
| לקוח | מי שאנחנו מוכרים לו | מספר לקוח, אימייל לחשבוניות, תנאי תשלום, מחירון, מסגרת אשראי, איש המכירות שלנו |
| ספק | מי שאנחנו קונים ממנו | מספר ספק, בנק, סניף, חשבון, תיק ניכויים, ניכוי במקור ותוקף האישור, תנאי תשלום |
| איש מכירות | אדם שמוכר — שלנו או שלהם | עמלה, אזור |
| איש קשר | אדם בארגון | תפקיד, מה הוא מקבל |

לכל ישות יש גם שדות משלה: טלפון, נייד, אימייל, רחוב, עיר, מיקוד, אתר והערות. קשר מחבר אדם לארגון («עובד/ת ב», עם
תפקיד), ואיש מכירות ללקוח («מטפל/ת ב»).

## כל הלשכה לוקחת משם

- **המסמכים**: «לקוחות» של ספר החשבונות הם הלקוחות של «ישויות». בפעם הראשונה ש«ישויות» עונה בלשכה, ספר החשבונות
  מעביר אליה בעצמו את הלקוחות הישנים שלו, פעם אחת. לקוח שנוסף מטופס של מסמך נוסף כאן. מסמך שהונפק שומר את הצדדים
  כפי שהיו ביום ההנפקה.
- **הבלוק שמסמך מדפיס** (`party`): השם, ח״פ, סטטוס המס, הכתובת, הטלפון, אימייל החשבוניות ואיש הקשר.

## לא מוחקים

ישות עוברת **לארכיון**: היא יוצאת מכל רשימה, ועדיין עונה לפי המזהה שלה, כי מסמך יכול לציין אותה. כל שינוי נרשם:
מי שינה, מתי, ומה היה לפני ואחרי. תפקיד שהוסר שומר ביומן את הפרטים שהיו בו.

## מי פותח

«ישויות» פתוחה למנהלי הלשכה. מנהל משנה רשומות רק מהמסך של היישום עצמו. שירות (ספר החשבונות, תהליך) קורא וכותב עם
המפתח של היישום.

```bash
./bbox apps enable entities
./bbox run
./bbox entities list customer
./bbox entities show ent_…
./bbox entities party ent_…
```
