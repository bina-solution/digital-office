## הבעיה

לשכה מריצה עשרות אפליקציות על מחשב אחד.
כל אחת צריכה כתובת, כניסה, סודות, נתונים ומקום בתור ההפעלה, וחלקן צריכות זו את זו.
מי שמחבר את כל זה ביד מקבל מערכת שאף אחד לא יודע לבנות שוב.

## הרעיון, שכבה אחרי שכבה

### התיקייה היא השכבה

- `platform/` היא שכבה 0: המהדר.
- `platform-base/` היא שכבות 1–2: מה שכל לשכה מקבלת.
- `apps/` היא שכבה 3: תיקייה אחת לכל אפליקציה.

אפליקציה מצהירה על עצמה בקובץ `app.json`.
המהדר הופך את ההצהרות ואת המצב של הלשכה לתיקייה `.generated/`, ‏Docker Compose מריץ את מה שנוצר, ו-Traefik הוא הדלת.

### מההורדה ועד לשכה רצה

מה קורה מהרגע שמריצים `git clone` ו-`./bbox run` ועד שהלשכה עובדת:

1. `bbox` טוען את `scripts/lib.sh`. על macOS כל פקודה עוברת לתוך המנוע (Lima), ועל Windows ‏`bbox.cmd` מעביר אותה לתוך WSL.
2. קבלה: הענף של הלשכה, המנוע, מקום אחד לעבודה כבדה (מנעול ורצפת זיכרון), ודיסק.
3. הקובץ `.env` והסודות מוכנים, ואז `platform/manager/reconcile.py render` מהדר.
4. המהדר טוען כל `app.json`, טוען את המצב, בודק, **פותר** (אילו אפליקציות דולקות, איזו אפליקציה נותנת כל יכולת שאחרת צריכה, ובאיזה סדר) ו**כותב** את `.generated/`: קובץ compose אחד שכולל את ה-compose של כל אפליקציה לפי הסדר, תוויות הניתוב, החיבורים, הרשימות שהמרכז קורא, ההקשר של הסוכנים, והתוכנית של האפליקציות שעוברות בין לשכות מקושרות.
5. לכל אפליקציה: `hooks/prepare`, אחר כך `docker compose up --wait`, ואחר כך `hooks/refresh` ו-`hooks/onboard`.
6. «ניהול אפליקציות» (`app-management`) משלים את מה שנשאר, וההרצה מדפיסה את הבעיות שלה.

### החוזה שכל אפליקציה חותמת עליו

הסכמה: `platform/schema/app.schema.json`.

| שדה | מה הוא עושה |
|---|---|
| `id`, `layer`, `kind`, `people` | הזהות; איפה האפליקציה רשאית לגור; `people: admins` שם את הדלת של המנהלים בלבד על הכתובות שלה |
| `capabilities[]` | מה היא **נותנת**: יכולת עם שם, עם כתובת או ממשק (ה-API שלה) והפעולות שלה |
| `use[]` | מה היא **צריכה**: יכולת, באיזו חוזקה (`requires` מושך ספק, `wants` לא), ובאיזה סדר |
| `routing[]` | הכתובות, הפורטים והכניסה (`sso`, אלא אם נאמר אחרת), ו-`module`: האריח שלה במרכז |
| `compose`, `connections[]`, `data`, `health`, `agent.context` | השירותים; הסודות שהיא רושמת; הנפחים; הבדיקה; התדריך שלה לסוכן (`AGENT.md`) |
| `hooks/<verb>` (קבצים, לא שדה) | שורת הפקודה שלה: `bbox <app> <verb>` מריץ את `apps/<id>/hooks/<verb>` |

### המצב

- `platform.state.default.yaml` הוא ברירת המחדל של המוצר: 17 אפליקציות דולקות.
- `platform.state.yaml` הוא הבחירה של לשכה אחת: אילו אפליקציות דולקות, ומה מגיע מלשכות מקושרות.
- `.env` מחזיק הגדרות וסודות. `BUSINESS_NAME` הוא השורה האחת שלשכה חדשה עורכת, והשאר נגזר ממנה.

### ארבעה ערוצים

כל אפליקציה מתבקשת לתת ארבעה ערוצים: **מסך** (כתובת ואריח), **שורת פקודה** (`hooks/`), **API** (יכולת עם כתובת), ו**זרם אירועים** (`dgo:flow:<app>`).
נכון ל-10 בנובמבר 2026: ל-57 אפליקציות יש מסך, ל-60 שורת פקודה, ל-48 API מוצהר ול-18 זרם אירועים. ל-15 מתוך 70 יש את כל הארבעה.

### מה כל לשכה מקבלת: הבסיס

| יחידה | בעברית | מה היא |
|---|---|---|
| `traefik` · `https-redirect` | נתב הקצה | הקצה על הפורטים 80 ו-443 |
| `forward-auth` · `authentik` | זהות וכניסה | הכניסה. ‏`forward-auth` הוא ברירת המחדל מאוקטובר, ו-`authentik` נשאר גיבוי |
| `postgres` · `redis` | בסיס נתונים · מטמון ותורים | Postgres אחד משותף ו-Redis אחד: מטמון, תורים, מנעולים וזרם האירועים |
| `connections` | חיבורים ומפתחות | הכספת של הסודות, ומתווך שמזהה מי מבקש |
| `app-management` · `containers` | ניהול אפליקציות · מכולות | ההתקנה, ההדלקה והכיבוי — דרך המהדר |
| `console` | המרכז | המעטפת: אריח לכל אפליקציה, כל אפליקציה בכתובת `/a/<alias>/` |
| `bina-ui` | ספריית ממשק | הפלטה האחת («Olive Grove») והרכיבים המשותפים |
| `machine` · `security` | מכונה · אבטחה | הנתונים של המחשב; יומן הדלת (בלשכות שרת) |
| `notifications` · `glitchtip` · `autoheal` | התראות · מעקב שגיאות · ריפוי עצמי | התראות; מעקב שגיאות (כבוי כברירת מחדל); הפעלה מחדש של קונטיינר שנפל |
| `data-management` | ניהול נתונים | גיבוי ושחזור |
| `follow-runner` | מעקב אחרי הגרסה היציבה | לוקח כל 30 דקות את הגרסה הירוקה החדשה של הענף שב-`DGO_FOLLOW` |

## מה זה מאפשר

- אפליקציה חדשה היא תיקייה עם `app.json`. המהדר מוצא לה מקום, כתובת, כניסה וסודות.
- אותה הצהרה בונה את אותה לשכה על כל מחשב, ולכן אפשר להעלות לשכה מחדש מתוך המאגר וקובץ `.env`.
- היכולות שאפליקציה נותנת וצריכה כתובות בקובץ, ולכן אפשר לראות מה תלוי במה בלי לקרוא קוד.
