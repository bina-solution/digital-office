## למה

הלשכה עלתה. עכשיו צריך למצוא אותה, להיכנס אליה לפני כל אחד אחר, ולשמור את קובץ ההגדרות.

## לפני שמתחילים

`./bbox run` הסתיים (על Windows `bbox.cmd run`).

## השלבים

1. **מצאו את הכתובת.** הכתובות של הלשכה הן ערכי `*_BASE_URL` בקובץ `.env`. המרכז הוא `CONSOLE_BASE_URL`.
   - על macOS: `http://console.localhost:8080`.
   - לשכה מקומית על לינוקס (בלי דומיין, `DGO_LOCAL=1`): `http://console.localhost`.
   - לשכה עם דומיין, על לינוקס או Windows: הערך של `CONSOLE_BASE_URL` ב-`.env`, שנגזר משם העסק: `console.<slug>.digital-office.co.il`.

   > TODO-product: לשכת Windows בלי דומיין. עוד לא נמדד אם `bbox.cmd install windows` משאיר את הלשכה מקומית כמו `DGO_LOCAL=1` בלינוקס.

2. **היכנסו ראשונים.** לשכה חדשה מגיעה בלי משתמשים. בהרצה הראשונה `./bbox run` מדפיס קישור חד-פעמי:

   ```
   [forward-auth] first run: open <כתובת הכניסה>/setup?code=<קוד>&rd=<כתובת המרכז>
   ```

   פתחו את הקישור, כתבו שם וסיסמה של 12 תווים לפחות, ואתם המנהל הראשון של הלשכה, ומחוברים.
   הקישור עובד עד שנוצר המנהל, ואף פעם לא אחרי. אל תשלחו אותו לאף אחד: מי שפותח אותו ראשון הוא המנהל.

   ![הכרטיס שיוצר את המנהל הראשון של לשכה חדשה](TODO-shot: הכרטיס של /setup בלשכת הדגמה חדשה; שולחן עבודה 1440x900, ערכה בהירה; ובטלפון 390x844)

3. **בדקו את הלשכה.** הראשונה מראה את מצב הקונטיינרים, והשנייה בודקת את הלשכה ויוצאת בלי שגיאה כשהכול תקין:

   ```bash
   ./bbox status
   ./bbox verify
   ```

   בלשכה חדשה לא מריצים את `./bbox onboarding`: היא מחכה כארבע דקות ל-n8n, שכבויה בלשכה חדשה, ומסיימת ב-«n8n REST not ready yet».

   רק לבדוק שוב את ההרשאות ולקבל קישורי התחברות מחדש:

   ```bash
   ./bbox onboarding --auth-state
   ```

4. **שמרו על `.env`.** הוא מחזיק את כל הסודות של הלשכה, והוא לא נכנס ל-`git`. אל תשמרו סודות בקבצים אחרים במאגר.

## איך בודקים שזה עבד

- נכנסתם למרכז וראיתם את האריחים.
- `./bbox status` מראה את הקונטיינרים תקינים.
- `./bbox verify` יוצא בלי שגיאה.

## ניקוי

`./bbox stop` מוריד את הלשכה ושומר את הנתונים.
`./bbox reset` **מוחק את כל הנתונים**, ושואל לפני כן.
