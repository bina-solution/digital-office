## למה

הנתונים של הלשכה (מסדי נתונים, קבצים, הגדרות של אפליקציות) לא נמצאים בתיקייה של המאגר. הם בנפחים של Docker.
לכן מחיקת התיקייה לא מוחקת אותם, ומחיקת הנפחים לא מוחקת את התיקייה. כל צעד כאן אומר מה הוא מוחק.

## לפני שמתחילים

- רוצים לשמור משהו? קודם [גיבוי](/he/backup).
- כל הפקודות רצות מתוך התיקייה של הלשכה. ב-Windows כל `./bbox` הוא `bbox.cmd`.

## השלבים

1. **לעצור, ולשמור את הנתונים.** הקונטיינרים יורדים והנתונים נשארים. `./bbox run` מעלה את הלשכה שוב, כמו שהייתה.

   ```bash
   ./bbox stop
   ```

2. **למחוק את כל הנתונים של הלשכה.** הפקודה שואלת לפני שהיא מוחקת. היא מוחקת את כל הנפחים של הלשכה הזו: מסדי הנתונים, Redis, n8n ושאר האפליקציות. אין דרך חזרה בלי גיבוי.

   ```bash
   ./bbox reset
   ```

3. **להסיר את מה שהותקן, לפי המחשב:**

   - **macOS:** המנוע של הלשכה הוא מכונה וירטואלית משלה. הפקודה הזו מוחקת את הדיסק שלה, ואיתו כל אימג׳, קונטיינר ונפח של הלשכה במק. היא דורשת `--force`:

     ```bash
     ./bbox engine destroy --force
     ```

     כל מה שהמנוע הוריד והקים נמצא בתיקייה `~/.bbox/macos`. מחיקת התיקייה מסירה את המנוע כולו.
   - **Windows:** הלשכה ו-Docker שלה רצים בתוך ההפצה `Ubuntu` של WSL, וגם הנפחים נמצאים בתוכה. `wsl --unregister Ubuntu` מוחק את הדיסק של ההפצה, ואיתו את כל הנפחים. הפקודה מוחקת גם כל דבר אחר שיש לכם בהפצה הזו. רוצים לשמור עותק? מריצים קודם `wsl --export Ubuntu <file>`. אחרי המחיקה נשארים קובץ `.wslconfig` ורכיבי WSL של Windows. הם לא נמחקים.
   - **לינוקס:** Docker נשאר מותקן. הלשכה התקינה אותו (גרסה 28, נעולה), אבל הוא כלי של המחשב, והסרתו היא הסרה רגילה של Docker.

4. **למחוק את התיקייה של המאגר.** בתיקייה נמצא גם `.env`, ובו כל הסודות של הלשכה. אם עוד תרצו להרים את הלשכה מהגיבוי, שמרו אותו קודם במקום בטוח.

## איך בודקים שזה עבד

- אחרי `./bbox stop`: הפקודה `./bbox status` לא מראה קונטיינרים רצים.
- ב-macOS, אחרי `./bbox engine destroy --force`: הפקודה `./bbox engine status` מדפיסה `not created`. בודקים לפני שמוחקים את `~/.bbox/macos`, כי בלי התיקייה הפקודה מורידה את הרכיבים של המנוע מחדש.
