## למה

הצעדים של ההתקנה כתובים כך שגם סוכן יכול להריץ אותם: פקודה אחת שמריצה את צעדי המדריך, ופלאגין של Claude שיודע לבצע אותם.
כמה צעדים נשארים שלכם בכל מקרה: סיסמת המחשב, אתחול אחד ב-Windows, והכניסה הראשונה ללשכה.

## לפני שמתחילים

- מחשב שעומד ב[דרישות](/he/start/requirements).
- סוכן שמריץ פקודות במסוף של המחשב הזה. סוכן שרץ על מחשב אחר לא יכול להתקין אצלכם.
- `git` מותקן. בלינוקס: `sudo apt-get install -y git`. במק: `xcode-select --install`.

## הדרך הקצרה: פקודה אחת

אפשר להריץ אותה בעצמכם, או לבקש מהסוכן להריץ אותה:

```bash
curl -fsSL https://digital-office.co.il/install.sh | bash
```

מה היא עושה, לפי המחשב:

- **לינוקס (Debian או Ubuntu), בלי דומיין:** מורידה את המאגר לתיקייה `~/digital-office`, מריצה `DGO_LOCAL=1 ./debian-install.sh` ואחר כך `./bbox run`. התוצאה היא לשכה מקומית.
- **לינוקס, בשרת עם דומיין:** נותנים לה את שם העסק, והיא כותבת אותו לשורה `BUSINESS_NAME` בקובץ `.env`:

  ```bash
  curl -fsSL https://digital-office.co.il/install.sh | DGO_BUSINESS_NAME=MyOffice bash
  ```

  שם העסק: אותיות באנגלית, ספרות ומקף בלבד.
- **macOS:** מורידה את המאגר ומריצה `./bbox run`, שמקים את המנוע של הלשכה.
- **Windows:** הפקודה לא מתקינה. היא מדפיסה את שלוש הפקודות שמריצים ב-CMD או ב-PowerShell, כמו ב[התקנה על Windows](/he/start/install/windows).

אפשר לשנות שני דברים: `DGO_DIR` היא התיקייה (ברירת המחדל `~/digital-office`), ו-`DGO_REF` היא הענף או הגרסה להוריד.

## בעזרת Claude: הפלאגין

הלשכה היא גם פלאגין של Claude. ב-Claude Code:

```
/plugin marketplace add bina-solution/digital-office
/plugin install digital-office@digital-office
```

אחר כך כותבים לו «תתקין לי לשכה דיגיטלית». הוא שואל אם זה שרת עם דומיין או מחשב לנסות עליו, ומריץ את המסלול המתאים.
ב-claude.ai או באפליקציות של Claude מעלים את התיקייה `packaging/claude/skills/install-dgo/` שבמאגר כ-Skill.

## סוכן אחר

תנו לו את הכתובת [digital-office.co.il/llms.txt](https://digital-office.co.il/llms.txt). זה הקובץ שסוכנים קוראים, והפקודה כתובה בראשו. למשל:

> התקן את הלשכה הדיגיטלית DGO במחשב הזה לפי https://digital-office.co.il/llms.txt. אל תקליד בשבילי אף סיסמה, ובסוף תן רק לי את הקישור שמכיל ‎/setup?code=‎.

## מה נשאר רק לכם

- **סיסמת המחשב.** כש-`sudo` מבקש סיסמה, אתם מקלידים אותה ולא הסוכן.
- **ב-Windows, פעם אחת:** פותחים PowerShell כמנהל, מריצים `wsl --install -d Ubuntu`, מפעילים את המחשב מחדש ופותחים את Ubuntu פעם אחת.
- **הכניסה הראשונה.** בסוף ההרצה מודפסת שורה עם קישור שמכיל `/setup?code=`. מי שפותח אותו ראשון הוא המנהל של הלשכה. פתחו אותו בעצמכם, ואל תעבירו אותו לאף אחד, גם לא לסוכן. אחרי זה ממשיכים ב[אחרי ההתקנה](/he/start/after-install).
- **הקובץ `.env`.** הוא מחזיק את כל הסודות של הלשכה. סוכן לא צריך להדפיס אותו.

## איך בודקים שזה עבד

- הפקודה מסיימת בכתובת המרכז, כפי שהלשכה רשמה אותה ב-`CONSOLE_BASE_URL` בקובץ `.env`.
- `./bbox status` מראה את הקונטיינרים תקינים, ו-`./bbox verify` יוצא בלי שגיאה.
