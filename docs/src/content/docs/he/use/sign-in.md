## למה

כל אפליקציה בלשכה נמצאת מאחורי כניסה אחת. בלשכה חדשה, שירות הכניסה הוא `forward-auth` («זהות וכניסה»). הבעלים נוצר פעם אחת, ואחר כך הוא מזמין אנשים.

## לפני שמתחילים

- לשכה חדשה שעלתה ב-`./bbox run`.
- גישה למסוף של המחשב שמריץ את הלשכה.

## השלבים

1. **מצאו את הקישור של ההפעלה הראשונה.** בהרצה הראשונה, `bbox run` כותב במסוף שורה שמתחילה ב-`[forward-auth] first run: open`. אחריה בא קישור לדף `/setup` עם קוד חד־פעמי.

   הקישור עובד עד שנוצר בעלים, ואף פעם לא אחרי.

2. **צרו את הבעלים.** פתחו את הקישור בדפדפן. בחרו שם וסיסמה של 12 תווים לפחות. הדפדפן נכנס, ומגיע למרכז.

   ![כרטיס ההפעלה הראשונה: שם וסיסמה](TODO-shot: forward-auth /setup עם קוד תקף, לשכת הדגמה, שולחן עבודה 1440x900 וטלפון 390x844, ערכה בהירה)

3. **הזמינו אדם נוסף.** מהמסוף:

   ```bash
   ./bbox forward-auth invite <user> <email> [display]
   ```

   הפקודה מדפיסה קישור חד־פעמי. שלחו אותו לאדם בעצמכם. הקישור תקף 7 ימים. הזמנה חדשה לאותו אדם מחליפה את הקישור הקודם.

4. **האדם בוחר סיסמה.** הוא פותח את הקישור, רואה כרטיס עם השם שלו ושני שדות סיסמה (12 תווים לפחות), ונכנס.

## מה אדם שהוזמן רואה

אדם שהוזמן פותח את האפליקציות של הלשכה, חוץ מאפליקציות של מנהלים בלבד. אפליקציה מסמנת את זה ב-`app.json` שלה (`people: admins`). רשימת האפליקציות האלה ב[דף האפליקציות](/he/apps).

## לנהל הזמנות

ההזמנות שעדיין לא נוצלו:

```bash
./bbox forward-auth invite --list
```

לבטל הזמנה:

```bash
./bbox forward-auth invite --revoke <user>
```

## איך בודקים שזה עבד

- נכנסתם למרכז עם השם והסיסמה שבחרתם.
- `./bbox forward-auth invite --list` כבר לא מראה את מי שנכנס.

## כשמשהו לא עובד

- **הקישור אומר שהוא לא תקף.** ההזמנה פגה, נוצלה, או הוחלפה. צרו הזמנה חדשה.
- **הרבה ניסיונות כניסה שגויים.** אחרי חמש טעויות, הכתובת נחסמת ל-60 שניות, והזמן מוכפל עד שעה.
- **אין שורת `first run` במסוף.** כבר יש בעלים בלשכה.
