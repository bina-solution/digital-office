## למה

לפני שינוי, אחרי שינוי, וכשמשהו נראה לא בסדר: בודקים מה רץ, מה מוכן, ומה כתוב ביומנים.

## לפני שמתחילים

- מסוף בתיקייה של הלשכה.

## השלבים

1. **מה רץ:**

   ```bash
   ./bbox status
   ```

   תמונת מצב: הקונטיינרים, האוטומציות וההרשאות. קונטיינר נספר כנופל רק אם האפליקציה שלו דולקת.

2. **האם הלשכה מוכנה:**

   ```bash
   ./bbox verify
   ```

   בודק את המחשב, את הלשכה ואת ההרשאות. יוצא עם קוד שאינו אפס כשמשהו שבור.

3. **מה כתוב ביומנים:**

   ```bash
   ./bbox logs
   ./bbox logs <svc> -f
   ```

   בלי שם: היומנים של כל השירותים, 200 השורות האחרונות. `-f` ממשיך לעקוב.

4. **כמה מקום וזיכרון נשארו:**

   ```bash
   ./bbox machine overview
   ./bbox machine storage
   ```

   הראשונה: מעבד, זיכרון, דיסק, ומה כל קונטיינר צורך. השנייה: מה תופס את הדיסק.

5. **ההרשאות לשירותים חיצוניים:**

   ```bash
   ./bbox onboarding --auth-state
   ```

   בודק שוב, ומחזיר קישורים לחיבור מחדש.

## איך בודקים שזה עבד

- `./bbox verify` יוצא בקוד 0.
- `./bbox status` לא מראה קונטיינר נופל.

## מה לא לעשות כשמשהו נופל

- לא `./bbox reset`. הוא מוחק את כל הנתונים.
- לא `docker compose` ישיר. ראו [מה לא לעשות](/he/admin/never-do).

## מחשב נייד שמריץ לשכה

```bash
./bbox host-power status
```

אומר אם המחשב מוגדר לא להירדם ולא להתחמם. ההתקנה (`install`) דורשת `sudo`.
