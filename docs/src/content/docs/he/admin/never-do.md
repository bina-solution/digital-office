## תקציר

כל אחת מהפעולות כאן מסתיימת בלי הודעת שגיאה. הנזק מופיע אחר כך, ונראה כמו בעיה אחרת.

## הרשימה

| לא לעשות | מה קורה | מה כן |
|---|---|---|
| `docker compose` ישיר | `compose.yml` מחזיק רק את הרשת המשותפת. הפקודה מוצאת אפס שירותים ויוצאת בהצלחה, בלי לעשות דבר. | `./bbox` או `./scripts/dc` |
| `docker compose -f apps/<app>/docker-compose.yml` | נפתח פרויקט שני עם אותם שמות קונטיינרים. ההרצה הבאה של `bbox run` נעצרת על «already in use». | `./bbox run` |
| `docker cp` לתוך קונטיינר כפריסה | השינוי חי רק עד שהקונטיינר נבנה מחדש, ו-`bbox run` בונה מחדש. | `./bbox update <app>` |
| לערוך קבצים ב-`.generated/` | זה פלט של המהדר. ההרצה הבאה כותבת אותו מחדש. | לשנות `app.json` או `platform.state.yaml` |
| Docker 29 בלי `DOCKER_MIN_API_VERSION=1.24` | הנתב של הלשכה עולה, מדווח שהוא תקין, ולא מנתב כלום. בלי שגיאה. | Docker 28.x, או Docker 29 עם `DOCKER_MIN_API_VERSION=1.24` |
| לגבות ב-`zip` של התיקייה | מסדי הנתונים, האוטומציות, המסמכים והמשתמשים נמצאים מחוץ לתיקייה. הלשכה תעלה ולא תדע כלום. | `./bbox export` |
| לשמור סודות מחוץ ל-`.env` | `.env` לא נכנס ל-`git`. קבצים אחרים במאגר כן. | `.env` |
| `./bbox reset` כדי «לנקות» | הפקודה **מוחקת את כל הנתונים**. | `./bbox stop` שומר את הנתונים |

## אם זה כבר קרה

**שמות קונטיינרים מוזרים**, שמתחילים ב-12 תווים ואחריהם `_`: אלה שאריות של פרויקט שני. הסירו אותם והעלו מחדש:

```bash
docker ps -a --format '{{.Names}}' | grep -E '^[0-9a-f]{12}_' | xargs -r docker rm -f
./bbox run
```

הפקודה הראשונה מוחקת קונטיינרים. היא לא מוחקת נתונים שבנפחים.
